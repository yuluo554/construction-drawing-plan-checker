# 02 总体技术路线与系统架构

## 1. 设计原则

1. **规则优先、LLM 兜底**：能用解析器/正则/规则引擎得到确定结果的绝不用大模型"猜"，LLM 负责非结构化语义理解和兜底抽取 → 结果可复现、可解释；
2. **证据可溯**：每个抽取参数携带来源（图纸图号+页码+bbox / 方案章节号+原文片段），每条校核结论携带依据（规范条款号/规则 ID）；
3. **中间表示统一**：图纸与方案解析产物统一为**工程参数卡（Parameter Card）**，校核即参数卡对齐比对——这是"协同"的核心；
4. **Agent 编排、确定性流水线**：主流程是确定性 pipeline（保证稳定），Agent 负责任务调度、异常恢复、补充探索与报告生成（体现"智能体"）。

## 2. 系统总体架构（六层）

```
┌─────────────────────────────────────────────────────────────┐
│ ⑥ 应用层   工作台 │ 图纸预览(高亮) │ 方案视图 │ 校核面板 │ 报告导出 │ 问答 │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 协同校核层  一致性校验 │ 关键指标核查 │ 危大合规判断 │ 报告生成   │
├─────────────────────────────────────────────────────────────┤
│ ④ 智能层    Agent编排(LangGraph) │ RAG检索(bge+FAISS) │ LLM抽取/多模态 │
├─────────────────────────────────────────────────────────────┤
│ ③ 表示层    工程参数卡(统一JSON本体) + 证据坐标 + 置信度           │
├─────────────────────────────────────────────────────────────┤
│ ② 解析层    PDF解析 │ OCR+版面 │ CAD解析(ezdxf) │ 表格提取 │ 平法解析 │
├─────────────────────────────────────────────────────────────┤
│ ① 接入层    上传管理 │ 格式转换(DWG→DXF/ODA) │ 任务队列 │ 进度推送 │
└─────────────────────────────────────────────────────────────┘
        支撑：规范知识库(条文库+规则库+危大清单)   数据与日志存储
```

## 3. 技术选型

| 类别 | 选型 | 理由 |
|------|------|------|
| 后端 | Python 3.10 + FastAPI + Celery/RQ | 生态全（PDF/CAD/OCR/LLM SDK），异步任务队列 |
| 前端 | Vue3 + PDF.js + Element Plus | PDF 渲染 + bbox 高亮定位成熟方案 |
| PDF 解析 | PyMuPDF(fitz) + pdfplumber | 文本/矢量/bbox 提取 + 表格提取 |
| OCR/版面 | PaddleOCR + PP-StructureV3 | 中文图纸扫描件识别，表格/版面还原 |
| CAD 解析 | ezdxf（DXF）；DWG 用 ODA File Converter 转 DXF | 开源稳定，图层/实体/文本/标注可编程读取 |
| 多模态理解 | Qwen2.5-VL / GLM-4V（API） | 扫描图纸图像问答：图框内容、图名、表格截图 |
| 文本抽取/Agent | GLM / Qwen / DeepSeek API（可切换），LangGraph 编排 | 国产模型合规易得；LangGraph 状态机适合校核流水线 |
| 向量检索 | bge-m3 + FAISS（或 Chroma） | 条文级语义检索 |
| 规则引擎 | 自研 JSON 规则 DSL + Python 执行器 | 规则可审阅可增删，透明可解释 |
| 部署 | Docker Compose（web/api/worker/db） | 评委一键起环境 |

## 4. 端到端数据流

```
上传图纸(PDF/DWG) + 方案(docx/pdf)
   │ ①接入层：格式转换、任务入队
   ▼
②解析层：
   图纸 → [矢量PDF: 文本层+矢量+表格] / [扫描: OCR+版面] / [DXF: 实体+图层+标注]
        → 图框/标题栏识别 → 图纸目录 → 分区(平面/立面/剖面/大样/说明)
        → 平法标注解析 + 表格(柱表/门窗表/材料表)提取
   方案 → docx/pdf → 章节树 → 表格/计算书识别
   ▼
③表示层：两路结果 → 工程参数卡（实体-属性-值-证据-置信度）
   例：{entity:"梁KL1", attr:"截面", value:"300x600", unit:"mm",
        source:{doc:"结施-12", page:3, bbox:[..], raw:"KL1(3) 300×600"}, conf:0.97}
   ▼
④智能层：Agent 调度
   - 低置信度字段 → LLM/多模态复核（把对应图纸区域裁图给 VLM 二次确认）
   - 规范问答/依据检索 → RAG
   ▼
⑤校核层（详见 plan/03）：
   A. 一致性校验：图纸参数卡 × 方案参数卡 对齐 → 差异清单
   B. 指标核查：规则引擎 + 计算工具（阈值/复算）
   C. 合规判断：危大识别 → 专项方案/专家论证义务 → 方案章节完整性
   ▼
⑥应用层：问题分级列表 + 双文档证据高亮 + 校核报告(docx/pdf导出)
```

## 5. Agent 设计

**主控（Supervisor）+ 工具调用**，工具清单：

| 工具 | 功能 | 确定性 |
|------|------|--------|
| `parse_drawing` | 调用解析层，产出图纸参数卡 | 确定性 |
| `parse_plan` | 调用方案解析，产出方案参数卡 | 确定性 |
| `align_cards` | 参数卡实体对齐（别名归一：如"砼"=“混凝土”） | 确定性 |
| `rule_check` | 执行规则库 JSON 规则（阈值/一致性/存在性） | 确定性 |
| `kb_search` | 规范条文向量检索（返回条款号+原文） | 确定性 |
| `calc` | 参数复算（配筋面积、立杆间距允许值、荷载） | 确定性 |
| `vlm_inspect` | 图纸区域裁图 → 多模态模型复核 | LLM |
| `report_gen` | 汇总问题清单 → 生成校核报告 | LLM |

**LangGraph 工作流**（节点=阶段，边=状态转移，带重试与人审挂起）：

```
intake → parse(图纸) ┐
                     ├→ align → check(规则) → [低置信度?] → vlm复核 → 汇总 → report
         parse(方案) ┘                    ↘ (kb_search 取依据)      ↘ export
```

要点：
- **校核主路径全部确定性工具**，Agent 不自由发挥数值结论，杜绝幻觉进入报告；
- LLM 只做：字段抽取兜底、别名归一、复核裁图、报告行文；
- 每个节点产物落库（JSON），支持断点续跑与评审回放。

## 6. 核心创新点（对应"创新性"评分）

1. **工程参数卡中间表示**：把"图纸↔方案协同"问题归约为结构化数据对齐问题，协同可计算；
2. **平法标注专用解析器**（规则+LLM 混合）：面向 22G101 平法体系的梁/柱/板配筋信息自动提取，行业针对性强；
3. **规则引擎 + RAG 双通道合规判断**：确定性规则给结论、RAG 给条文依据，报告每条可溯源；
4. **危大工程自动识别**：基于 31 号文附件阈值表的机器可读清单，从方案/图纸参数自动判定"危大/超规模→专项方案/专家论证"义务；
5. **（前沿探索）参数联动生成**：图纸参数变更 → 自动生成方案修订建议文本 + 简易图元更新演示。
