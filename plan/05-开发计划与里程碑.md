# 05 开发计划与里程碑（含风险应对）

## 1. 团队分工建议（4人示例，可按实际调整）

| 角色 | 职责 |
|------|------|
| A 算法-图纸方向 | PDF/OCR/CAD 解析、平法解析器、参数卡构建 |
| B 算法-文档方向 | 方案解析、LLM 抽取、RAG 知识库、规则引擎 |
| C 工程后端 | FastAPI 服务、任务队列、Agent 编排、数据库 |
| D 前端+产品 | Vue3 界面、PDF 高亮交互、报告生成、演示视频 |
| 全员 | 数据标注、测试、技术报告章节分写 |

## 2. 里程碑（8 周，每周一个可演示目标）

| 周 | 目标 | 可演示成果 | 关键产出 |
|----|------|-----------|----------|
| W1 | 需求确认+架构冻结+数据启动 | 技术路线图评审通过；**联系命题单位拿到首批案例** | 需求规格、接口定义、data/ 初版 |
| W2 | 图纸解析 v1 | 矢量 PDF → 图框/表格/文本块 → 原型页面可见 | M1 v1、20 张标注样本 |
| W3 | 方案解析 v1 + 参数卡 Schema 定稿 | docx 方案 → 章节树+参数卡 JSON | M2 v1、Schema v1.0 |
| W4 | 知识库+规则引擎 v1 | 30 条规则跑通，危大识别可演示 | M3 v1、危大清单 JSON |
| W5 | 一致性校验+Agent 编排 v1 | 图纸×方案对齐出差异清单（命令行可用） | M4 v1、LangGraph 流程 |
| W6 | 前端集成+端到端打通 | **全流程 demo**：上传→解析→校核→高亮→报告导出 | M5 v1、Docker Compose |
| W7 | 评测+打磨+技术报告 | 评测集指标达标；报告初稿 | 评测报告、技术报告 v1 |
| W8 | 演示视频+提交材料定稿 | 5 分钟视频、打包提交 | 视频、代码包、材料清单 |

> 若周期只有 4–6 周：砍 W8 并入 W7；FR7/FR9 降级为可选；规则库一期缩到 30 条保演示。

## 3. 每周例会与验收

- 周一任务分解（issue 级）、周五 demo 验收（跑真实文件）；
- 每两周与命题单位沟通一次（要数据、对场景、纠偏差）。

## 4. 风险与应对

| # | 风险 | 概率/影响 | 应对 |
|---|------|-----------|------|
| 1 | 命题单位数据提供延迟 | 高/高 | 自制数据保底（ezdxf 程序化生成配筋图+公开范本方案），拿到真实数据后替换 |
| 2 | 扫描图纸质量差，OCR 失准 | 中/中 | 双通路设计（矢量优先）；VLM 复核；演示场景选矢量 PDF 为主、扫描为辅 |
| 3 | 平法写法变体多，解析精度不足 | 中/高 | 规则+LLM 混合 + 合法性校验拦截；评测集持续回归 |
| 4 | LLM 抽取幻觉（编造参数值） | 中/高 | 所有 LLM 值必须带原文引用并与原文 diff 校验；数值字段非法即弃 |
| 5 | 规范文本版权/获取困难 | 中/中 | 官方公开文件为主；条款引用而非全文分发；核心阈值自建核对表 |
| 6 | 大模型 API 不稳定/合规 | 低/中 | 多模型可切换（GLM/Qwen/DeepSeek）；关键路径不依赖 LLM |
| 7 | 范围蔓延（全专业/三维） | 中/中 | 严守 plan/01 §5 边界 |
| 8 | 演示当天环境故障 | 低/高 | Docker Compose 一键起 + 录屏备份视频 + 离线大模型降级方案 |

## 5. 质量保障

- 代码：模块化+单元测试（解析器/规则引擎核心逻辑覆盖率 ≥ 70%）；
- 回归：每入库一张标注样本即可跑自动评测脚本，指标看板记录；
- 安全：上传文件类型/大小白名单，任务沙箱执行。
